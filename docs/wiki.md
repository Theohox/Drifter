# Drifter Wiki

*The complete reference for Drifter — what it does, why it exists, how to use it, and where it can be improved. Audience: new users adopting Drifter on a fresh project, existing users, and contributors working to make Drifter more optimized, user-friendly, clean, and usable on any project.*

---

## 1. What Drifter Is

Drifter is a **cooperative guard for AI coding agents**. It is a Python CLI (v0.4.0, Python ≥ 3.10, hatchling build, PyPI distribution `drifter-check`, entry point `drifter = drifter.cli:main`) that watches a project for *drift* — the slow divergence between code, documentation, configuration, and stated intent — and enforces behavioral discipline on the agents (human or AI) working in the repo.

### Philosophy

AI agents fail in predictable ways: they recreate code that already exists, append without reading, skip tests, hallucinate file paths and command names, let docs rot, and occasionally run destructive shell commands. Drifter's bet is that these failure modes are **detectable and auditable** with cheap static checks plus an append-only session log — no heavyweight sandboxing required.

### The cooperative-guard model

Drifter is a **cooperative guard, not a mandatory gate**. It assumes the agent wants to comply. A misaligned agent can catch and ignore `DangerousCommandError`, skip `drifter check`, forge log entries (mitigated by HMAC signatures since v0.3.0), rewrite `dangerous_patterns.toml`, or delete `.drifter/` entirely. This is by design: Drifter raises the *cost* of mistakes and makes bypasses *auditable*; it does not make them impossible. For mandatory enforcement, layer on:

- Git pre-commit hooks (`drifter install-hook`) — run before every commit
- CI pipelines (see `.github/workflows/ci.yml` for this repo's example)
- A watchdog process outside the agent's execution context

### Core concepts

| Concept | What it is | Where it lives |
|---|---|---|
| **Drift** | Divergence between code, docs, config, and stated intent | Detected by the 35 checks in `src/drifter/checks/` |
| **Drift score** | 0–100 health score: `100 - min(errors,10)*10 - min(warns,25)*2` | `src/drifter/drift_guard.py` |
| **Session audit log** | HMAC-SHA256 signed append-only log of READ/WRITE/SHELL/CHECK actions | `.drifter/session.log` via `src/drifter/session_logger.py` |
| **Conductor** | A backlog document (`docs/project-conductor.md`) with exactly one active task, blocked/future/completed tables, and a drift score history | Managed by `src/drifter/conductor.py` |
| **Capability manifest** | Machine-readable JSON description of Drifter's own commands/checks/MCP tools, generated for LLM consumption | `.drifter/capability-manifest.json` via `src/drifter/manifest_generator.py` |
| **Structural manifest** | Hand-maintained TOML declaring every file in the repo, check counts, and numeric claims docs must match | `drifter-manifest.toml` |
| **dangerous_patterns.toml** | Single source of truth for which shell commands agents may never run | Repo root |
| **AGENTS.md** | The agent contract read before every session | Repo root (template: `src/drifter/templates/AGENTS.md.tmpl`) |

## 2. Getting Started

### Install

The PyPI distribution is named `drifter-check` (the CLI command stays `drifter`; `pip install drifter` would get an unrelated 2015 package). PyPI publishing is wired via tag-triggered trusted publishing (`.github/workflows/publish.yml`) — until the first tagged release lands there, install from a clone of the repository:

```bash
pip install .            # or: pipx install .
# dev extras (pytest, ruff, mypy):
pip install ".[dev]"
# once published on PyPI:
# pip install drifter-check
```

Drifter is a standard hatchling project. The only runtime dependency is `tomli` on Python < 3.11 (see `pyproject.toml`). The console script `drifter` and `python -m drifter` (via `src/drifter/__main__.py`) are equivalent.

### `drifter init` on a fresh project

Run `drifter init` at the project root. It creates:

| Path | Source |
|---|---|
| `AGENTS.md` | `src/drifter/templates/AGENTS.md.tmpl` |
| `dangerous_patterns.toml` | `src/drifter/templates/dangerous_patterns.toml.tmpl` |
| `drifter.toml` | `src/drifter/templates/drifter.toml.tmpl` |
| `docs/session-protocol.md` | `src/drifter/templates/session-protocol.md.tmpl` |
| `docs/project-conductor.md` | `src/drifter/templates/project-conductor.md.tmpl` |
| `docs/digests/index.md` | `src/drifter/templates/digest-index.md.tmpl` |
| `docs/archive/README.md` | `src/drifter/templates/archive-readme.md.tmpl` |
| `docs/methodology.md`, `docs/architecture.md`, `docs/adoption-guide.md`, `docs/rules-reference.md` | Inline stubs generated by `_doc_stub()` in `src/drifter/_cli_init.py` — **only with `--full`** |

Templates are shipped as package data inside the wheel and resolved with `importlib.resources` via `src/drifter/_templates.py` (repo-root `templates/` fallback for bare source checkouts). If a template is genuinely missing, `init` aborts with a hard error instead of writing placeholder stubs. Templates get `{{PROJECT_NAME}}` and `{{NOW}}` substitution. Existing files are skipped unless `--force` is passed.

### `drifter init` on an existing project

Same command. Without `--force` nothing you already have is overwritten; gaps are filled in. Then:

1. Edit `AGENTS.md` with your project specifics.
2. Edit `dangerous_patterns.toml` to match your risk tolerance.
3. **Disable the Drifter-self-specific checks** (see sections 4 and 11) or they will nag you about a codebase layout you don't have.
4. Run `drifter check` and iterate.

## 3. CLI Command Reference

Parser construction and dispatch live in `src/drifter/cli.py`; command handlers live in the `_cli_*` modules (`_cli_check`, `_cli_conductor`, `_cli_init`, `_cli_admin`, `_hook_commands`, `_commit_commands`). Global flag: `--root <dir>` to operate on a different project root. Every command exits non-zero on failure, so all are CI-safe.

### `drifter check`

Runs the drift guard — all enabled checks from `drifter.toml` in parallel (ThreadPoolExecutor, 4 workers).

| Flag | Effect |
|---|---|
| `--score` | One-liner: `DRIFT: N issues | E errors | W warns | SCORE: X%`. Gotcha: the score is 0–100 *points*, printed with a `%` sign (`src/drifter/_cli_check.py`). |
| `--format console\|json\|github` | Output format. `github` emits `::error file=...::` / `::warning ...` workflow annotations; `json` emits the metadata envelope with structured issue objects |
| `--json` | Deprecated alias for `--format json` |

Exit code: 1 if any error-severity issue exists, else 0.

### `drifter preflight`

Runs the 7-step pre-flight protocol (`src/drifter/pre_flight.py`): (1) AGENTS.md exists, (2) session protocol exists, (3) conductor exists, (4) **full drift guard run**, (5) conductor has an active task, (6) grep `src/` for a keyword, (7) `dangerous_patterns.toml` exists. Also touches the conductor's `updated:` timestamp on success.

| Flag | Effect |
|---|---|
| `--task "..."` | Recorded with the run: shown in the report header and logged to the session log as a TASK entry |
| `--keyword X` | Step 6 greps Python files under `src/` for X (native Python, no subprocess) |

Gotcha: step 4 runs the entire check suite, so `preflight` costs roughly 2× a bare `check` when you run both.

### `drifter conductor <sub>`

Manages `docs/project-conductor.md` (falls back to a root-level `project-conductor.md`).

| Subcommand | What it does |
|---|---|
| `init [--force]` | Writes the conductor from `src/drifter/templates/project-conductor.md.tmpl` |
| `show` | Prints phase + active task (regex-parsed) |
| `done --task-id ID [--evidence "..."]` | Marks the active task ✅ COMPLETE, writes an archive file under `docs/archive/` named `<task-id>-<slug>.md`, appends a Completed Tasks row |
| `block --task-id ID --reason "..."` | Appends a row to the Blocked Tasks table |
| `next` | Prints a **static hint** ("check the conductor manually") — it does not actually parse future tasks |

Gotcha: `done`/`block` require `--task-id` but the matching logic ignores it — they always operate on the *active* task block / append a row with the given ID (`src/drifter/conductor.py`).

### `drifter validate`

Validates frontmatter and type rules on every markdown file in `docs/` plus root-level `*.md` (root-level exemptions: `README.md`, `AGENTS.md`, `CONTRIBUTING.md`, `CHANGELOG.md` — the last exempt since 0.4.0). Rules enforced by `src/drifter/_doc_validate.py`:

- Frontmatter block required (error if missing)
- `type:` must be one of: constitution, snapshot, backlog, archive, playbook, guide, reference, index
- `status:` one of active, draft, archived, deprecated (warn)
- `phase:` must be an integer; `version:` must be semver-ish (warn)
- `title:`, `created:`, `updated:` expected (warn); `updated` older than `created` is an error
- `snapshot` bodies over 10k chars get a "split me" warn

Gotcha: any unexpected root-level markdown needs full frontmatter or it errors — but a conventional root `CHANGELOG.md` is exempt since 0.4.0 (`src/drifter/doc_validator.py`).

### `drifter audit`

Scans recent shell history against `dangerous_patterns.toml` via `HistoryReader` + `ShellGuard`.

| Flag | Effect |
|---|---|
| `--window N` | How many recent history entries to check (default 100) |
| `--no-history` | Skip the history scan entirely |

Gotcha: if no history file is found it prints a notice and exits 0 — a silent pass, not a failure.

### `drifter init`

Scaffolds the project (see section 2). Flags: `--force` (overwrite existing), `--full` (also create the four optional doc stubs: methodology, architecture, adoption-guide, rules-reference — minimal mode writes only the seven template-backed files). Templates resolve via `importlib.resources` (`src/drifter/_templates.py`), so `init` works from an installed wheel; a missing template is a hard error, never a placeholder stub.

### `drifter log <READ|WRITE|SHELL|CHECK> <target>`

Appends a signed entry to `.drifter/session.log`. This is how agents prove diligence: log every read, write, shell command, and drift check.

### `drifter log-rotate`

Archives the current session log to `.drifter/session.log.<timestamp>` and starts a fresh one. Use it when adopting a new Drifter version on a project whose old log trips current behavioral checks (legacy entries, cross-project paths).

### `drifter session-report`

Generates the behavioral report card over the session log: counts reads/writes/shells/tests/drift-checks, then runs the four behavioral checks (read_before_write, test_after_write, drift_check_after_write, no_rush). Exit 1 if any issue. Test runs and drift checks are classified by the shared `is_test_run`/`is_drift_check` helpers in `src/drifter/checks/behavioral.py` (word-boundary `pytest` match; CHECK-action entries always count as drift checks).

### `drifter install-hook` / `drifter uninstall-hook`

Installs/removes a git pre-commit hook (`.git/hooks/pre-commit`) that runs `drifter check` and blocks the commit on error-level drift (`src/drifter/_hook_commands.py`). Refuses to overwrite an existing hook — uninstall or back it up first.

### `drifter manifest`

Scrapes the Drifter codebase itself (AST over `src/drifter/`, `plugins/mcp-server/server.py`, `src/drifter/reporters/`) and writes `.drifter/capability-manifest.json`.

### `drifter describe [--format json|markdown]`

Prints the capability manifest — a machine-readable description of Drifter's commands, checks, MCP tools, reporters, and doc types, intended for LLM consumption.

## 4. The Check Catalog

35 built-in checks, registered in `BUILTIN_CHECKS` in `src/drifter/checks/__init__.py`. Severity below is the **default ceiling** from `DEFAULT_CONFIG` in `src/drifter/config.py` — per-check `severity` config is applied by the engine as a ceiling (issues report at no higher severity; escalation is not possible).

Scope column: **U** = universal (any project), **C** = universal mechanism but assumes Drifter doc conventions (`docs/` layout, conductor, digests), **S** = Drifter-self-specific (only makes sense when the target repo *is* Drifter).

### Documentation checks — `src/drifter/checks/docs.py`

| Check | Sev | Scope | What / Why |
|---|---|---|---|
| `stale_reference` | warn | U | Extracts backticked paths, markdown links, and bare path tokens from all markdown and verifies the referenced file exists. Kills hallucinated path citations. Skips `docs/archive/` (historical records). |
| `cross_doc_consistency` | warn | U | Verifies that relative markdown links between docs resolve against the linking file's directory. |
| `timestamp_staleness` | warn | U | Flags docs whose frontmatter `updated:` is >1h older than the file mtime — catches edits that forgot to bump the timestamp. |
| `digest_staleness` | warn | C | Flags digests in `docs/digests/` containing PENDING/TODO/BLOCKED/WAITING items older than `max_pending_age_days` (default 7). |
| `archive_integrity` | error | C | Every markdown file in `docs/archive/` (except its README) must have frontmatter with `type: archive` and a `task_id` matching its filename prefix. Keeps the archive machine-navigable. |

### Security checks — `src/drifter/checks/security.py`

| Check | Sev | Scope | What / Why |
|---|---|---|---|
| `credential_leak` | error | U | Regex-scans source files for API keys (OpenAI, GitHub, GitLab, AWS), bearer tokens, private key blocks, hardcoded passwords/secrets/tokens, credentialed URLs, and 40-char base64-ish strings. Skips tests, comments, and obvious placeholders. |
| `git_safety` | error | U | Scans source for git mutation commands (`commit`, `push`, `reset`, `rebase`, `merge`, `cherry-pick`, `tag`, `checkout -b`) in strings/subprocess/os.system calls. Code that commits on its own is drift. |
| `dangerous_patterns` | error | U | Verifies `dangerous_patterns.toml` exists, parses, has `[git]`/`[shell]` sections, and is referenced in `AGENTS.md`. Without it agents have no command boundaries. |
| `gitignore` | error | U | If files matching `filesystem.sensitive_patterns` exist in the repo, the pattern must appear in `.gitignore`. |

### Project-state checks — `src/drifter/checks/project.py`

| Check | Sev | Scope | What / Why |
|---|---|---|---|
| `conductor_health` | error | C | Conductor exists, has exactly one Active Task section, and a phase marked ACTIVE. |
| `pipeline_integrity` | error | C | Task IDs unique across Active/Blocked/Future/Completed; `Depends On` references exist and are acyclic; blocked tasks have a "Blocked On"; completed tasks have evidence. A ~240-line regex/DFS method. |
| `conductor_content` | warn | C | Drift Score History table is non-empty; active task evidence isn't a placeholder. |

### Drifter-self sync checks — `src/drifter/checks/sync.py`

All seven assume the target repo is Drifter itself. **Disable these on any other project.**

| Check | Sev | Scope | What / Why |
|---|---|---|---|
| `architecture_doc_sync` | warn | S | `docs/architecture.md`'s listed check/CLI counts match the actual `src/drifter/checks/` and `src/drifter/cli.py`; `src/drifter/templates/drifter.toml.tmpl`'s hardcoded count matches too. |
| `pre_flight_sync` | warn | S | `pre_flight.py`'s step count agrees with `docs/session-protocol.md`, `docs/methodology.md`, and `README.md`; both code and protocol mention `dangerous_patterns.toml`. |
| `readme_completeness` | warn | S | `README.md` mentions the canonical artifacts and commands (lenient if the README predates Drifter files). |
| `doc_coverage` | warn | S | `AGENTS.md` mentions every module and CLI command; README mentions key features; `dangerous_patterns.toml` matches its template byte-for-byte. |
| `cli_output` | warn | S | `cmd_init`'s output text mentions all canonical files. |
| `audit_coverage` | error | S | `cmd_audit` handles every action type `ShellGuard` can return. |
| `reporter_completeness` | error | S | `src/drifter/reporters/console.py` references all three severity levels. |

### Structure checks — `src/drifter/checks/structure.py`

Driven by the hand-maintained `drifter-manifest.toml`; they silently no-op if it's absent.

| Check | Sev | Scope | What / Why |
|---|---|---|---|
| `tree_integrity` | error | S | Every file on disk is declared in `[tree.*]` and every declared file exists. Warns on orphans, errors on missing. |
| `file_size` | error | S | No declared file exceeds its `max_lines` (global default `[structure] max_file_lines = 300`). Errors if the manifest is unparseable, warns on oversize files. |
| `manifest_sync` | error | S | `[checks] count`/`names` match the AST-scanned check classes; `.drifter/capability-manifest.json` (if present) matches actual CLI commands and MCP tools. |
| `claim_sync` | error | S | `[claims]` regex patterns in named docs (e.g. "35 automated checks" in `README.md`) match manifest values. |

### Code-quality checks — `src/drifter/checks/code_quality.py`

| Check | Sev | Scope | What / Why |
|---|---|---|---|
| `dead_code` | warn | U | Python modules under `src/` with zero imports (including `__init__.py` re-exports) and zero tests. |
| `test_coverage` | warn | U | Every `src/` module has a matching test file under `tests/` named `test_<module>.py` (with fallbacks for check modules: name match or import match). |
| `tomllib_compatibility` | error | U | Bare `import tomllib` without a 3.11 version guard — crashes on Python 3.10. |
| `hardcoded_path` | error | U | Quoted paths starting with `docs/`, `src/`, `tests/`, etc. in source files must exist on disk. |

### Behavioral checks — `src/drifter/checks/behavioral.py`

Session-log-based; also power `drifter session-report`.

| Check | Sev | Scope | What / Why |
|---|---|---|---|
| `read_before_write` | error | U | Every logged WRITE has a logged READ of the same target anywhere in the log (two-pass, so post-compaction reads count). The #1 agent failure mode is append-without-reading. |
| `test_after_write` | error | U | A SHELL entry containing `pytest` appears after the last WRITE. |
| `drift_check_after_write` | error | U | A SHELL/CHECK entry containing `drifter check` appears after the last WRITE. |
| `no_rush` | error | U | ≥1 drift check per 3 WRITEs (warn); ratio >10:1 or zero checks escalates to error. |

### Agent-behavior checks — `src/drifter/checks/agent_behavior.py`

| Check | Sev | Scope | What / Why |
|---|---|---|---|
| `agent_self_audit` | error | U | Scans the last 50 shell-history entries (only if `history_path` is configured) against `[agent] always_report` (error) and `approval_required` (warn). Silently passes without history — see section 10. |
| `git_commit_approval` | error | U | Last 5 git commits with destructive subjects (delete/remove/drop/destroy/rm -rf) must carry an `[APPROVED BY ...]` marker in the body. |

### Config & ghost checks

| Check | Sev | Scope | What / Why |
|---|---|---|---|
| `config_sync` | error | S | `src/drifter/config.py` `DEFAULT_CONFIG`, `drifter.toml`, and `src/drifter/templates/drifter.toml.tmpl` all agree with the manifest's check name list (`src/drifter/checks/config_sync.py`). |
| `ghost_reference` | warn | U | Scans markdown for backticked `drifter <cmd>` and `drifter_*` MCP tool references that don't exist in the capability manifest — catches hallucinated commands in docs (`src/drifter/checks/ghost_reference.py`). |

## 5. Core Module Map

Everything under `src/drifter/`. Layering is convention: checks may import core; core may not import cli/reporters/checks; plugins are leaves. (The `drifter-manifest.toml` `[boundaries]` section that once declared this was deleted — zero code consumers. SOW W13 proposes reintroducing it backed by import-linter.)

|---|---|---|---|
| `cli.py` | `main(argv)` | Parser construction + dispatch only; every subcommand wired via `set_defaults(func=...)` | — |
| `_cli_check.py` | `cmd_check`, `cmd_session_report` | `drifter check` delegates output to the reporters; session report card over the audit log | R: session log |
| `_cli_conductor.py` | `cmd_conductor` | All `drifter conductor` subcommands | RW: conductor |
| `_cli_init.py` | `cmd_init`, `cmd_validate`, `_doc_stub` | Scaffolding from bundled `src/drifter/templates/` (resolved via `_templates.py`) with `{{PROJECT_NAME}}`/`{{NOW}}` substitution; doc validation report | RW: project files |
| `_templates.py` | `template_text(name)` | Bundled template resolution via `importlib.resources` with a repo-root `templates/` fallback for bare source checkouts | R: package data |
| `_cli_admin.py` | `cmd_preflight`, `cmd_audit`, `cmd_log`, `cmd_log_rotate`, `cmd_manifest`, `cmd_describe` | Preflight also appends the drift score to the conductor; log-rotate archives the session log | RW: conductor, `.drifter/` |
| `config.py` | `Config.load(root, overrides)`, `Config.check_config(name)`, `is_ignored()`, `is_check_ignored()`; dataclasses `CheckConfig`, `IgnoreConfig` | Layered merge: `DEFAULT_CONFIG` → `drifter.toml` `[drifter]` (legacy `[tool.drifter]` also honored) → `pyproject.toml` `[tool.drifter]` → CLI overrides; `checks` lists merge per-`name`; fnmatch ignores; per-check `[drifter.check_config.<name>]` | R: `drifter.toml`, `pyproject.toml` |

| `conductor.py` + `_conductor_helpers.py` | `Conductor.init/show/mark_done/block_task/next_task/append_drift_score`; helpers `create_archive_file`, `default_conductor_content` | Regex and line-index surgery on the conductor markdown tables via the shared `_insert_table_row` helper; `mark_done` writes an archive file per completed task with the real score from Drift Score History; `append_drift_score` is called by `cmd_preflight` so Drift Score History self-populates | RW: `docs/project-conductor.md`, plus archive files under `docs/archive/` |

| `_hook_commands.py` | `cmd_install_hook`, `cmd_uninstall_hook` | Writes/removes `.git/hooks/pre-commit` (0755); refuses to overwrite a non-Drifter hook; `--approval` adds the human-approval gate | RW: `.git/hooks/` |
| `_commit_commands.py` | `cmd_approve`, `cmd_commit_msg` | Arms the one-time `.git/approved` token (human-only); drafts a commit message from the staged diff | RW: `.git/approved` |

## 6. Configuration Reference

### `drifter.toml` — layered resolution

`Config.load()` merges, in priority order (`src/drifter/config.py`):

1. Built-in `DEFAULT_CONFIG` (all 35 checks enabled with default severity ceilings)
2. `drifter.toml` at project root (`[drifter]` section, or root-level keys)
3. `pyproject.toml` `[tool.drifter]`
4. CLI `overrides` dict

Merge semantics: dicts merge recursively; `checks` entries merge **per `name`** —
a `[[drifter.checks]]` entry updates the default entry of the same name (omitted
fields keep their defaults) and unknown names are appended. A sparse config
therefore never disables unlisted checks; an explicit `checks = []` still wipes
the suite. Per-check `severity` is a **ceiling**: the engine demotes that check's
issues to at most the configured severity (`error` > `warn` > `info`). Escalation
is not possible — defaults are set to each check's maximum emitted severity.

Key settings:

| Key | Default | Meaning |
|---|---|---|
| `root` | `"."` | Project root |
| `max_pending_age_days` | 7 | Age threshold for `digest_staleness` |
| `drift_threshold` | 70 | Minimum score for `preflight` step 4 to pass |
| `history_path` | None | Explicit shell history path; enables `agent_self_audit` |
| `[[drifter.checks]]` | all 35 | `name`, `enabled`, `severity` per check; an optional `path` (relative to project root or absolute) loads a custom check class from a Python file — see `docs/architecture.md` §Custom Checks |
| `[drifter.check_config.<name>]` | — | Per-check overrides merged into the check's config |
| `[drifter.ignore].paths` | venv, node_modules, `.git/`, etc. | fnmatch ignore patterns applied to all checks |

### `dangerous_patterns.toml` — command boundaries

The single source of truth for what agents must never run. Consumed by `ShellGuard`, `drifter audit`, `agent_self_audit`, and the `dangerous_patterns`/`gitignore` checks.

| Section | Keys | Effect |
|---|---|---|
| `[git]` | `always_block`, `allowed`, `approval_required` | Git command classification (checked first, in that order) |
| `[shell]` | `blocked`, `confirm_required` | `blocked` → block; `confirm_required` → warn |
| `[filesystem]` | `system_dirs`, `sensitive_patterns` | Substring-matched: system dirs → block; sensitive files → approval_required |
| `[agent]` | `always_report`, `approval_required` | Enforced retroactively by `agent_self_audit` against shell history |

### The two manifests (naming collision — read this)

Drifter has **two unrelated files both called "manifest"**:

| File | Maintained by | Purpose |
|---|---|---|
| `drifter-manifest.toml` (repo root) | **Hand-maintained** | Structural truth for *this repo*: `[tree.*]` file declarations with `max_lines`, `[structure]` limits, `[checks]` count/names, `[claims]` doc-number regexes. Drives tree_integrity, file_size, manifest_sync, claim_sync, config_sync. |
| `.drifter/capability-manifest.json` | **Generated** by `drifter manifest` | Runtime description of Drifter's own capabilities for LLM consumers. Drives ghost_reference and is cross-validated by manifest_sync. |

If you adopt Drifter on another project, you almost certainly want neither at first — see section 11.

### `.drifter/` runtime directory

Created on demand, mode 0700, typically gitignored:

| File | Purpose |
|---|---|
| `session.log` | Append-only HMAC-signed audit log (0600) |
| `.session_secret` | 32-byte random HMAC key (0600) |
| `capability-manifest.json` | Output of `drifter manifest` |

## 9. The Behavioral Protocol

### Session logging

Agents log every significant action:

```bash
drifter log READ docs/wiki.md
drifter log WRITE docs/wiki.md
drifter log SHELL "pytest tests/ -q"
drifter log CHECK "drifter check passed 96/100"
```

Each entry is HMAC-SHA256 signed (signature truncated to 16 hex chars) with a per-repo secret, so hand-edited or forged entries are silently skipped on read. Log format: `[timestamp|pid|action|target|sig]`. Legacy unsigned entries still parse but are marked unverified.

### The report card

`drifter session-report` runs the four behavioral checks and prints counters. Passing means: every WRITE had a READ, the last WRITE was followed by a test run and a drift check, and the write:check ratio stayed ≤ 3:1. The log is your proof of diligence — if it shows you rushed, you cannot declare done.

### The git boundary rule

Agents do not commit. Agents do not push. Ever. `git status`/`diff`/`log`/`show`/`branch` are informational and allowed; `git add` requires explicit per-use approval; everything history-mutating is blocked. Each commit requires **fresh, verbatim** human approval — prior approval never rolls forward. `agent_self_audit` and `git_commit_approval` exist to catch violations after the fact.

## 11. Adoption Playbooks

### Fresh project checklist

1. `pip install .` (or pipx) from the Drifter repo.
2. `drifter init` at your project root.
3. Edit `AGENTS.md` (project specifics) and `docs/session-protocol.md` (your rules).
4. **Disable Drifter-self checks** (snippet below) — this is the step everyone forgets.
5. Add your active task to `docs/project-conductor.md`.
6. `drifter preflight` — should pass end to end.
7. `drifter install-hook` if you want pre-commit enforcement.
8. Add `.drifter/` to `.gitignore`.

### Existing / legacy project checklist

1. `drifter init` (no `--force` — your files are safe).
2. Start with a minimal check set. Disable initially: the seven `sync.py` checks (`architecture_doc_sync`, `pre_flight_sync`, `readme_completeness`, `doc_coverage`, `cli_output`, `audit_coverage`, `reporter_completeness`), the four `structure.py` checks (`tree_integrity`, `file_size`, `manifest_sync`, `claim_sync`), and `config_sync`. If you don't use the conductor convention yet, also disable `conductor_health`, `pipeline_integrity`, `conductor_content`, `digest_staleness`, `archive_integrity`.
3. Keep the universal wins on from day one: `credential_leak`, `git_safety`, `dangerous_patterns`, `gitignore`, `stale_reference`, `cross_doc_consistency`, `hardcoded_path`, `dead_code`, `test_coverage`, `tomllib_compatibility`, the four behavioral checks, `agent_self_audit`, `git_commit_approval`, `ghost_reference`.
4. Expect `credential_leak` false positives on legacy code — tune with `[drifter.check_config.credential_leak] ignore_paths` rather than disabling.
5. Re-enable convention checks (`conductor_*`, `digest_staleness`, `archive_integrity`) once you adopt the `docs/` workflow.

[[drifter.checks]]

[[drifter.checks]]
name = "readme_completeness"

[[drifter.checks]]
name = "doc_coverage"
enabled = false

[[drifter.checks]]
name = "cli_output"
enabled = false

[[drifter.checks]]
name = "audit_coverage"
enabled = false

[[drifter.checks]]
name = "reporter_completeness"
enabled = false

[[drifter.checks]]
name = "tree_integrity"

[[drifter.checks]]

### CI usage

`drifter check` exits 1 on any error-severity issue, so it drops straight into a pipeline:

```yaml
- name: Drift guard
  run: |
    pip install .
    drifter check --format github   # workflow annotations on PRs
    # or: drifter check --score     # one-line gate
```

This repo's own workflow is `.github/workflows/ci.yml`. Combine with `drifter install-hook` locally for defense in depth: the hook catches drift pre-commit, CI catches anything that slipped through.
